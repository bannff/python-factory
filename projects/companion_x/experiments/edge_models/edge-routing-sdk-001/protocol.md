**Status:** N=2 attestation v2, host collector, sealed-image source/preflight contracts, and a two-peer SDK runner have synthetic contract coverage. No reviewed image pins, built routing image, launcher, routed live Ditto SDK run, trusted review receipt, or routing training label exists.

## Purpose and boundary

The planned run will test whether one frozen specialist observation can create a task, select one eligible peer, obtain an accepted result, and converge across two offline Ditto SDK peers. The deterministic coordinator remains the authority. An optional learned router may later rank eligible peers but cannot authorize membership, resolve claims, or execute an action. The planned run uses Linux ARM64; iPhone, physical radio, and N=4 heterogeneous-device claims require separate runs.

Build a sibling sealed routing image around this collector. Preserve ENG-184's pinned observation-only image and its fixed evidence allowlist. Reuse its owned-container, internal-network, secret-mount, bounded collection, and cleanup patterns without widening that image's frozen inputs.

## Implemented evidence contract

[`attestation_schema.py`](attestation_schema.py) defines frozen, strict Pydantic v2 records for exact run pins, a two-candidate predecision snapshot, selected Claim/Result, per-peer local writes and reopen/rejoin queries, reducer digests, and a reviewer receipt. [`attestation.py`](attestation.py) verifies an attestation against **caller-supplied expected pins**, a caller-supplied mapping from concrete Capability IDs to task skill tags, and a caller-supplied trusted key policy mapping `key_id` to `(reviewer_id, Ed25519 public key)`. Neither the attestation nor receipt can nominate its own trust root.

The verifier checks that both candidate peers and their Capability records were authorized and effective at decision **and** selection time, including intervening Capability revisions and Session membership epochs. It requires the coordinator's Session/Observation/Task and each peer's advertised Capability to appear as that peer's local write and survive its reopen query; the selected peer must likewise locally write and reopen the Claim/Result. Attestation v2 also requires an actual coordinator SDK query **before** decision that contains the cited Session, Observation, Task, and both Capabilities with matching hashes. Query timestamps cannot precede returned records, each rejoin query must contain the complete matching record set, and rejoin must follow reducer evaluation. It then replays the pinned `records.py`/`reducer.py` bytes and requires the selected Claim and completed Result to be the reducer's accepted winner. A reviewer receipt must accept exact attestation, execution, and outcome digests and verify under the externally trusted reviewer identity/key.

These checks validate the **contents of supplied evidence**. They do not establish that Docker containers, Ditto SDK calls, peer disconnection/rejoin, or an independent reviewer actually produced it. The focused tests use signed synthetic fixtures and negative mutations; they are contract evidence, not a live routing experiment. Local records/reducer modules are currently imported before their hashes are checked; a future sealed runner must verify exact source bytes before import and execute from immutable image contents.

[`collection_schema.py`](collection_schema.py) and [`collect_sealed.py`](collect_sealed.py) add the host-owned ENG-207 collection boundary. It checks externally supplied pins, one owned stopped image on an internal network with a read-only secret mount, exactly three bounded run/peer-query files for success or an index-only early failure, peer readback consistency, and reducer replay. It constructs an **unreviewed** v2 attestation from the copied SDK documents, including the coordinator's predecision query; it does not accept a container-authored attestation or hold a reviewer signing key. The collector stages private, synced evidence before Docker cleanup, publishes only after final identity/cleanup checks, and retains that stage on later failure. The latest collector changes passed fresh read-only review. These tests use a fake Docker boundary and do not prove real SDK provenance or Docker behavior.

[`sealed_image.py`](sealed_image.py) and [`sealed_entrypoint.py`](sealed_entrypoint.py) define the sibling image's exact source allowlist, immutable reviewed-pin input, fixed entrypoint, license-free preflight, and Sandbox profile for an internal ARM64 run. [`run.py`](run.py) and [`peer.py`](peer.py) exercise two separate SDK stores: each peer scores a locally preloaded image, the worker reads the Task through its own SDK query before Claim and inference, and a worker-only offline backlog must reach the coordinator after reopen/rejoin. The worker replays the pinned reducer against its reopened store. These behaviors have fake-SDK contract tests; they do not establish live Ditto sync. The combined attestation, collector, sealed-image, and runner suites pass 128 focused tests; Ruff passes. Fresh review found the missing in-image Pydantic dependency and measurement evidence described below; the prior task-delivery and replay gaps are closed in the tested path.

No reviewed pins have been issued, and the routing image has not been built or preflighted. The sealed image still needs a pinned Pydantic v2 dependency for reducer replay. The evidence schema does not yet carry declared resource ceilings or database, raw SDK stream, write, and delivery metrics, so no performance acceptance claim is supported.

## Trust and Dataset handoff

The collector emits a canonical, content-addressed **unreviewed** run attestation binding the decision snapshot, selected candidate, Claim, Result, SDK observations, peer readbacks, and all frozen digests. An independent reviewer must inspect actual collector evidence and sign a receipt over its digest plus execution/outcome digests, verdict, and review time. Dataset verification must obtain expected pins, Capability-to-skill mapping, and trusted reviewer identity/key from policy outside the example row or artifact. A self-supplied key or a plausible JSON `ditto_sdk_live` field is insufficient. The current Dataset quality gate does not yet consume these attestations; ENG-206 now re-verifies completed-job artifacts before exposing training URIs but keeps routing label publication fail-closed.

Only the actually attempted route has an observed outcome; unchosen candidates are censored. `edge_routing_example` quality remains fail-closed until it can verify the collector attestation and reviewer receipt on every read. One accepted N=2 episode proves the evidence path but cannot populate independent train, validation, and untouched test splits. Preserve episode, session, source-event, and evidence-digest isolation before any routing model training. Test-only synthetic rows exercise parser and negative gates, not model quality.
